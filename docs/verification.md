## 组合策略的真实验证

从真实 Arena 数据中冻结两个历史决策，在独立预算账本中使用完整 `HybridPolicy`：两次 Jev 路由均选择无需分析，耗时 895 ms / 836 ms，最终都为 fold。共两次 Jev 请求，估算费用 $0.000216846，零次 Claude 调用。此结果证明门控的直接路径可用，不能证明自然触发了完整三步链路。

另外做一次独立 Messages 扑克分析探针，最多 512 输出 token，12 秒 deadline。请求超过 deadline 后取消，usage 未知且账本保留费用预留；因为没有得到分析，没有调用 Jev reconsider。该探针不属于 Jev 自然路由，不计为端到端组合成功。

完整的 Jev → reasoning → Jev 分支、异常降级与模型不一致通过可控响应测试验证。仓库默认策略保持纯 Jev；服务器按部署配置启用组合策略，不宣称其真实扑克表现更好。

提高分析 deadline 到 30 秒后，另一次真实历史扑克样本使用 `claude-opus-5` Messages、`thinking: { type: 'adaptive' }` 和 1,200 输出 token 上限，分析成功，再由 `jev-1.13.0` reconsider 成功选择合法 check。共两次付费调用，使用独立有界账本。这证明启用思考的分析及 Jev 二次决策可用；它是显式 provider 探针，不等同于 Jev 自然门控触发的三步 Arena 实测。
