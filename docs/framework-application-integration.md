# Production assembly and configuration migration

The server and bot CLI use one `LiveDecisionCoordinator`, `FactsService` and `DuelLoopResearchService`. Live actions accept only `jev`; baseline and synchronous Jev + reasoning remain isolated offline evaluation/diagnostic adapters. No old advice worker is started or attached as a live input. Old research HTTP GET data remains a read-only legacy archive.

The runtime keeps the existing account lease and OpenPoker socket. A prior run must settle decisions before its coordinator closes or a replacement starts. Normal stop drains the current hand; lease renewal continues until settlement. Decision receipts and feedback are flushed before SDK storage closes. Background facts/research lifetimes remain separate from bot stop.

New persistence paths are `FACTS_DATABASE_PATH` (default raw path + `.facts.sqlite`) and `DUELLOOP_DATABASE_PATH` (default raw path + `.duelloop.sqlite`); they must differ from raw and legacy databases, including symlink aliases. `DUELLOOP_ACTOR_ID` and `DUELLOOP_SCOPE_ID` are stable deployment identities, never process run IDs. `DUELLOOP_EXECUTION_RESERVE_MS` defaults to 1500. Old knowledge/research paths stay available for history readers. `FACTS_ENABLED` controls deterministic facts; `RESEARCH_ENABLED` remains a documented legacy alias only when `FACTS_ENABLED` is absent.

`BOT_STRATEGY=baseline` and `BOT_STRATEGY=jev-reasoning` are rejected for live startup. All `ASYNC_LLM_*` and `LLM_ADVICE_*` settings, plus `REASONING_MODE` and `HYBRID_TIMEOUT_MS` are retired live controls: remove them after migrating to explicit `DUELLOOP_RESEARCH_*` settings. Keys remain backend-only and can be reused by offline diagnostic adapters. `DUELLOOP_RESEARCH_ENABLED` defaults false; enabling requires the configured Jev/DeepSeek keys. Missing or invalid independent protocol files put research in `waiting_protocol` while live Jev decisions continue. Old automatic advice publication is never interpreted as strategy activation approval.

Public `/api/framework` is a whitelist projection of release IDs, facts pin, execution reconciliation and research status. Authenticated operations separately pause/resume research, cancel a run, recover a run, pause activation, approve a validated release and roll back a release. Operator identity/reason is recorded for release changes. Public viewers cannot change strategy or mutate bot state.

Create a private locked experimental plan with `npm run research -- --op prepare-protocols --output data/protocols --min-samples 30 --hands-per-seed 6 --minimum-improvement 0 --max-group-regression 25 --confidence 0.95 --max-latency-ms 40000`. These numbers are an explicit example, not empirically calibrated profitability criteria. The command generates fresh disjoint seed sets, writes development/final JSON with mode 0600 and refuses replacement. Choose the thresholds before final evaluation, using pilot variance where available. The default private paths are `data/protocols/development.json` and `data/protocols/final.json`; use `DUELLOOP_DEVELOPMENT_PROTOCOL` / `DUELLOOP_FINAL_PROTOCOL` for another location. After creating a missing plan, restart only research through the authenticated maintenance route.

`npm run research -- --op status` reads the public projection using the configured backend token. `pause`, `resume`, `cancel --run ID` and `recover` affect research only. `approve --release DIGEST --actor NAME --reason TEXT`, `rollback`, `pause-activation` and `resume-activation` require operator attribution. These commands contact the existing server; they never create a second local publisher. Historical paired Choice/advice utilities remain library-level offline compatibility tools and cannot publish through this CLI.
